Timing of the areal-augmented composite estimator (simE3_aug.py), one core, numpy + numba, 22 Sep 2026.

Per-block key sampler (block_mcmc: transposition Metropolis over both keys; 100 burn-in + 300 samples x thin 2 = 700 sweeps of K proposals each):
  K=  10:   0.8 ms per block  (0.11 us per proposal)
  K=  20:   1.4 ms per block  (0.10 us per proposal)
  K=  30:   1.7 ms per block  (0.08 us per proposal)
  K=  50:   3.2 ms per block  (0.09 us per proposal)
  K= 100:   7.6 ms per block  (0.11 us per proposal)
  K= 200:  26.4 ms per block  (0.19 us per proposal)
Each proposal is O(K) (update of Omega_b r), so a sweep is O(K^2) and the sampler is O(K^2 * sweeps) per block; no K! anywhere.

Full fit (areal GLS start, 10 damped Newton iterations, each iteration = one MCMC run per block with 150 samples):
  B=  64  K= 20  n= 1280:  0.5 s
  B= 100  K= 30  n= 3000:  0.7 s
  B= 100  K= 50  n= 5000:  2.4 s
  (B=400, K=30 was killed by memory in the benchmark's *data generation*, which builds the n x n covariance to simulate W;
   the estimator itself only needs the B block precisions Omega_b (K x K) and the B x B covariance V of the block sums.)
Blocks are independent given beta, so the per-block stage parallelises across cores with no communication.

For comparison, REPAIR's ELBO (revised_elbo.py) evaluates n_piX_sample x n_steps relaxed permutations per outer iteration with a full n x n Sigma_W update and an n x n eigendecomposition per iteration.
